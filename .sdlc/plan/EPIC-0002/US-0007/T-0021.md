# T-0021: Crear pool pgx compartido en `internal/platform/db.go`

## Descripción técnica:
Crear `internal/platform/db.go` [NUEVO] con `NewPool(ctx context.Context, databaseURL string) (*pgxpool.Pool, error)`: parsea la DSN, configura `MaxConns=5` y `MinConns=1` (pool chico, SPECS-002.6), y hace `Ping` con retry exponencial (1 s → 2 → 4 → …, máx. 30 s total, respetando `ctx`) antes de devolver el pool. El servicio NO ejecuta migraciones (las corre `rodritv-api`, EPIC-0001); solo verifica conectividad. Dependencias vía `go mod tidy`: `github.com/jackc/pgx/v5`.

## Pseudo código:
```
cfg, err = pgxpool.ParseConfig(databaseURL); cfg.MaxConns = 5; cfg.MinConns = 1
pool = pgxpool.NewWithConfig(ctx, cfg)
deadline = now + 30s; backoff = 1s
loop:
    err = pool.Ping(ctx); si nil: retornar pool
    si now > deadline o ctx.Done: cerrar pool, retornar error con %w
    sleep(backoff); backoff = min(backoff*2, 8s)
```

## Criterios de aceptación:
- [ ] Dado PostgreSQL accesible (testcontainers), `NewPool` devuelve pool funcional
- [ ] Dado DSN inválida o DB caída, `NewPool` devuelve error en ≤ 30 s + margen y libera el pool
- [ ] Dado `ctx` cancelado durante el retry, devuelve `ctx.Err()` envuelto

## Definición de finalizado (DoD):
- [ ] Tests unitarios de la lógica agregada/modificada en verde (integración con testcontainers para el caso feliz)
- [ ] Tests existentes sin romper

- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
