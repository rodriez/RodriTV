# T-0004: Crear servidor HTTP con middleware, mapeo uniforme de errores y `/healthz`

## Descripción técnica:
Crear `cmd/api/server.go` [NUEVO] con: `NewServer(cfg Config, log *slog.Logger, deps ...) *http.Server` que arma el `http.Server` (timeouts razonables: ReadHeader 5 s) sobre un `http.ServeMux` envuelto por middleware compuesto: (1) `requestID` (genera/propaga `X-Request-ID`), (2) `logging` (slog JSON con `request_id`, `method`, `path`, `status`, `duration_ms`), (3) `recover` (panic → 500 formato uniforme). Función `writeError(w, err)` con el mapeo uniforme: `ErrValidation`→400 `validation`, `ErrNotFound`→404 `not_found`, `ErrConflict`→409 `conflict`, resto→500 `internal` (los errores de dominio se definen en US-0002; aquí queda la función con el switch `errors.Is/As`). En `cmd/api/routes.go` [NUEVO]: `registerRoutes(mux *http.ServeMux, deps ...)` que por ahora registra solo `"GET /healthz"` → handler que ejecuta `pool.Ping` (o `SELECT 1`) y responde `200 {"status":"ok"}` o `503`. JSON siempre `application/json; charset=utf-8`.

## Criterios de aceptación:
- [ ] `GET /healthz` con DB viva responde 200 `{"status":"ok"}`; con DB caída responde 503
- [ ] Un panic en un handler devuelve 500 con el formato `{"error":{"code":"internal",...}}` y loguea el stack
- [ ] Cada request genera una línea de log JSON con los 5 campos estructurados

## Definición de finalizado (DoD):
- [ ] Tests unitarios de la lógica agregada/modificada en verde
- [ ] Tests existentes sin romper
- [ ] Lint/type-check sin errores (`go vet` y `gofmt` limpios)
- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
