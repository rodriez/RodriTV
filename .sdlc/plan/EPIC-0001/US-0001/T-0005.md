# T-0005: Crear `cmd/api/main.go` con composición y ciclo de vida

## Descripción técnica:
Crear `cmd/api/main.go` [NUEVO]: `LoadConfig()` → `slog` JSON con nivel de config → `platform.NewPool` → `platform.MigrateUp` (si falla distinto de `ErrNoChange`, `os.Exit(1)`) → construir server (T-0004) y registrar rutas → arrancar en goroutine → `signal.NotifyContext(SIGINT, SIGTERM)` → `Shutdown` con `ShutdownTimeout`. Inyección manual de dependencias (sin frameworks DI).

## Criterios de aceptación:
- [ ] Con DB vacía, el proceso migra y queda sirviendo `/healthz` en el puerto configurado
- [ ] Con migración fallida, el proceso sale con código != 0
- [ ] `SIGTERM` cierra conexiones en vuelo dentro del timeout y sale con código 0

## Definición de finalizado (DoD):
- [ ] Tests unitarios de la lógica agregada/modificada en verde
- [ ] Tests existentes sin romper
- [ ] Lint/type-check sin errores (`go vet` y `gofmt` limpios)
- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
