# T-0060: Crear fragmentos de lectura de canales y sus partials en `internal/panel/fragments.go`

## Descripción técnica:
Crear `internal/panel/fragments.go` [NUEVO] con:
- `ChannelListFragment`: `GET /frag/channels` → `api.ListChannels` → renderiza `partials/channel_list.html` [NUEVO] (ítems con número, nombre, logo `<img src="http://…:9290/logos/{logo}">` o placeholder de iniciales si no hay logo, indicador enabled y `stateClass`), usado para refrescar la sidebar.
- `ChannelDetailFragment`: `GET /frag/channels/{id}` → `api.GetChannel` → renderiza `partials/channel_detail.html` [NUEVO]: formulario de edición (nombre, número, logo — nombre de archivo resultante, solo lectura con hint de la convención `<channel_id>.<ext>` —, `schedule_url`, habilitado, `segment_seconds` 2–10) + grilla de 5 slots de sources (por slot: URL y checkbox habilitada; leyenda "slot más bajo ocupado = principal") + botones Guardar/Eliminar + contenedor del bottom (placeholder de métricas/logs hasta T-0065).
Registrar ambas rutas en `cmd/web/routes.go`. Tests con `APIClient` mockeado: verifican que el fragmento NO incluye el layout completo (sin `<html>`) y sí los elementos clave.

## Pseudo código:
```
ChannelDetailFragment(w, r):
    ch, err = api.GetChannel(ctx, id)
    si IsNotFound: render partial "no encontrado" + header HX-Trigger refreshList; return
    si err red: render banner "API no disponible"; return
    render.Render(w, "channel_detail.html", ch)
```

## Criterios de aceptación:
- [ ] `GET /frag/channels` devuelve solo el fragmento de lista (sin `<html>`/`<head>`) con un ítem por canal
- [ ] `GET /frag/channels/{id}` devuelve el formulario con los 5 slots renderizados (ocupados con URL, vacíos con inputs vacíos)
- [ ] Dado 404 de la API, el fragmento muestra aviso "canal no encontrado" y dispara refresh de la lista
- [ ] El logo se referencia al servidor de playlist `:9290/logos/{filename}`; sin logo se muestra placeholder
- [ ] Los inputs de número y segmento llevan `min`/`max`/`required` de validación en cliente
