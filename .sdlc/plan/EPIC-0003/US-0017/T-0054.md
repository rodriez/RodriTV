# T-0054: Implementar métodos de canales en `internal/apiclient/client.go`

## Descripción técnica:
Sobre la base de T-0053, implementar en `internal/apiclient/client.go` [NUEVO] los 5 métodos de canales de la interfaz `APIClient`, mapeando 1:1 con SPECS-001.5.1: `ListChannels` → `GET /v1/channels` (decodifica `{"channels": [...]}`), `GetChannel` → `GET /v1/channels/{id}`, `CreateChannel` → `POST /v1/channels` (201), `UpdateChannel` → `PUT /v1/channels/{id}` (reemplazo total; el `Channel` enviado incluye el array completo de 5 slots), `DeleteChannel` → `DELETE /v1/channels/{id}` (204, sin body de salida). Los `{id}` se escapan con `url.PathEscape`. Tests con `httptest.Server` que emula cada endpoint y cada código de error (400/404/409).

## Pseudo código:
```
ListChannels: do(GET, "/channels", nil, nil, &struct{Channels []Channel}) → retornar .Channels
CreateChannel: do(POST, "/channels", nil, ch, &created) → retornar created
UpdateChannel: do(PUT, "/channels/"+esc(id), nil, ch, &updated) → retornar updated
DeleteChannel: do(DELETE, "/channels/"+esc(id), nil, nil, nil)
```

## Criterios de aceptación:
- [ ] Dado `GET /v1/channels` con 2 canales (uno con slots nil), `ListChannels` devuelve 2 `Channel` con los slots nil preservados
- [ ] Dado `POST` que responde 409 (`conflict`, number duplicado), `CreateChannel` devuelve error con `IsConflict(err)==true`
- [ ] Dado `GET /v1/channels/x` que responde 404, `GetChannel` devuelve error con `IsNotFound(err)==true`
- [ ] `UpdateChannel` envía el body con las 5 posiciones del array `sources` (verificable en el handler de test)
- [ ] `DeleteChannel` ante 204 devuelve nil

- [ ] Tests existentes sin romper

- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
