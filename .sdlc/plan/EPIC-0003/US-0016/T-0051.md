# T-0051: Crear `cmd/web/routes.go` y `cmd/web/main.go` con `/healthz`

## Descripción técnica:
Crear `cmd/web/routes.go` [NUEVO] con `NewMux() *http.ServeMux` que por ahora registra solo `GET /healthz` (handler inline que responde `200` con body `{"status":"ok"}`; **no** consulta la API — SPECS-003.5: la UI ya muestra "API no disponible" en fragmentos). Las rutas de páginas, fragmentos y `/static/*` se agregan a esta función en T-0056, T-0059..T-0065 (firma prevista: `NewMux(ph *panel.Handlers, static http.Handler)`). Crear `cmd/web/main.go` [NUEVO]: composición manual — `LoadConfig()` (error → `slog.Error` + `os.Exit(1)`), construcción del `slog` JSON con nivel de cfg, `NewMux()`, middleware (`withRecover` envolviendo `withLogging`), `NewServer` y `Run` con `signal.NotifyContext(SIGINT, SIGTERM)`.

## Pseudo código:
```
main():
    cfg, err = LoadConfig(); si err: exit 1
    logger = slog.New(JSONHandler{Level: cfg.LogLevel})
    mux = NewMux()
    srv = NewServer(cfg, withRecover(withLogging(mux, logger)), logger)
    ctx = signal.NotifyContext(SIGINT, SIGTERM)
    si err := Run(ctx, srv, cfg.ShutdownTimeout); err != nil: exit 1
```

## Criterios de aceptación:
- [ ] `go build ./cmd/web` produce el binario; al ejecutarlo sin env vars escucha en `:9292`
- [ ] `curl localhost:9292/healthz` responde 200 con `{"status":"ok"}` aunque `rodritv-api` esté caída
- [ ] Cualquier otra ruta responde 404 del ServeMux
- [ ] `SIGTERM` apaga el proceso con exit code 0
