# T-0073: Crear `Makefile` raíz con todos los targets

## Descripción técnica:
Crear `Makefile` [NUEVO] en la raíz del repo según la tabla de SPECS-004.3. Variable `COMPOSE = docker compose -f deployments/docker-compose.yml`. Todos los targets `.PHONY`; `help` es el target por defecto (primero del archivo) y lista cada comando con su descripción (patrón `##` autodocumentado con grep/awk).

Targets:
- `up`: `$(COMPOSE) up -d --build`
- `down`: `$(COMPOSE) down`
- `logs`: `$(COMPOSE) logs -f $(S)` (`make logs S=api` filtra un servicio)
- `ps`: `$(COMPOSE) ps`
- `build`: `go build ./...`
- `test`: `go test ./... -coverprofile=cover.out` y luego excluir del coverage los archivos generados por sqlc (`grep -v -E 'internal/.*/(queries\.sql\.go|models\.go|db\.go)' cover.out > cover.tmp && mv cover.tmp cover.out` — patrón alineado con lo que genera T-0008 y ss.; el `.func` report se deriva de `go tool cover -func=cover.out`)
- `vet`: `go vet ./...`
- `generate`: `sqlc generate` (requiere sqlc instalado y `sqlc.yaml` de EPIC-0001 / T-0008)
- `release`: valida `TAG` presente (`make release TAG=x.y.z`) y ejecuta `scripts/release.sh $(TAG)`
- `clean`: `$(COMPOSE) down -v` + `rm -f cover.out`

## Criterios de aceptación:
- [ ] `make` (sin target) muestra `help` con todos los targets y sus descripciones
- [ ] `make build`, `make vet` y `make test` corren sobre el módulo Go y `cover.out` no incluye archivos `queries.sql.go`/`models.go`/`db.go` generados por sqlc
- [ ] `make release` sin `TAG` falla con mensaje claro; con `TAG=1.2.3` invoca `scripts/release.sh 1.2.3`
- [ ] `make up`/`down`/`logs`/`ps`/`clean` usan siempre `-f deployments/docker-compose.yml`
- [ ] Todos los targets declarados `.PHONY`

## Definición de finalizado (DoD):
- [ ] Cada target ejecutado al menos una vez en local (los de compose con `config -q` válido; `up` completo cuando existan los binarios)
- [ ] Tests existentes sin romper
- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
