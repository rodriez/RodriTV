# T-0069: Crear `deployments/docker-compose.yml` con 4 servicios, healthchecks y orden de arranque

## Descripción técnica:
Crear `deployments/docker-compose.yml` [NUEVO] con red bridge interna `rodritv` y 4 servicios, todos `restart: always` y `stop_grace_period` acorde al `SHUTDOWN_TIMEOUT` de cada binario (15–20 s; SPECS-004.3):

- **`db`** (`container_name: rodritv-db`): imagen `postgres:17-alpine`; env `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB` desde `.env`; volumen `~/.rodritv/db:/var/lib/postgresql/data`; **sin `ports`** (solo red interna); healthcheck `pg_isready -U $${POSTGRES_USER}`; `mem_limit: 512m`.
- **`api`** (`container_name: rodritv-api`): `build: { context: .., dockerfile: build/api/Dockerfile }`, imagen `rodritv-api:${TAG}`; env `DATABASE_URL=postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@rodritv-db:5432/${POSTGRES_DB}?sslmode=disable`, `DATA_DIR=/data`, `PORT=9291`, `TZ=${TZ}`; volumen `~/.rodritv/data:/data`; `ports: "9291:9291"`; `depends_on: db (condition: service_healthy)`; `mem_limit: 256m`.
- **`playlist`** (`container_name: rodritv-playlist`): build con `build/playlist/Dockerfile`, imagen `rodritv-playlist:${TAG}`; env `DATABASE_URL` (misma DSN), `STREAMING_DIR=/streaming`, `DATA_DIR=/data`, `LOGS_DIR=/logs`, `TZ=${TZ}`; volúmenes `~/.rodritv/streaming:/streaming`, `~/.rodritv/logs:/logs`, `~/.rodritv/data:/data:ro`; `ports: "9290:9290"`; `depends_on: db (service_healthy)` y `api (service_started)`; `shm_size: 512m`; `mem_limit: 2g`.
- **`web`** (`container_name: rodritv-web`): build con `build/web/Dockerfile`, imagen `rodritv-web:${TAG}`; env `API_URL=http://rodritv-api:9291`, `TZ=${TZ}`; `ports: "9292:9292"`; `depends_on: api (condition: service_healthy)`; `mem_limit: 256m`.

Los healthchecks de `api` y `web` que consume el `depends_on` los aporta el `HEALTHCHECK` de cada Dockerfile (T-0066, T-0067); no duplicarlos en compose. Validar con `docker compose -f deployments/docker-compose.yml config -q`.

## Criterios de aceptación:
- [ ] `docker compose config -q` valida sin errores con un `.env` de ejemplo
- [ ] `db` no publica ningún puerto al host (verificable en `config` y en `docker compose ps` tras el up)
- [ ] El orden de arranque queda declarado: db(healthy) → api → playlist(started sobre api) / web(healthy sobre api)
- [ ] Volúmenes y límites `mem_limit` coinciden con SPECS-004.3 (db 512m, playlist 2g, api/web 256m; `shm_size: 512m` solo en playlist)
- [ ] Smoke test (cuando existan los binarios): `up -d --build`, los 3 `/healthz` responden 200, `down` limpio

## Definición de finalizado (DoD):
- [ ] `docker compose config -q` en verde
- [ ] Smoke test de arranque completo verificado en local (requiere EPIC-0001/0002/0003; si aún no existen, se mergea con `config -q` en verde y se deja el smoke para el cierre de la EPIC)
- [ ] Tests existentes sin romper
- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
