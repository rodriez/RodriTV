# T-0066: Crear `build/api/Dockerfile` multi-stage

## Descripción técnica:
Crear `build/api/Dockerfile` [NUEVO] con dos etapas. Build: `FROM golang:1.27-alpine AS build`, `WORKDIR /src`, copiar primero `go.mod`/`go.sum` y `go mod download` (caché de capas), luego copiar el resto y compilar con `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/rodritv-api ./cmd/api`. Runtime: `FROM alpine:3.21`, `apk add --no-cache ca-certificates`, crear usuario no-root `rodritv` (uid 1000, `adduser -D -u 1000 rodritv`), copiar el binario a `/app/rodritv-api`, `USER rodritv`, `EXPOSE 9291`, `HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD wget -qO- http://localhost:9291/healthz || exit 1`, `ENTRYPOINT ["/app/rodritv-api"]`. El contexto de build es la raíz del repo (se define en compose, T-0069).

## Criterios de aceptación:
- [ ] Dado el binario `cmd/api` existente (EPIC-0001), `docker build -f build/api/Dockerfile -t rodritv-api:test .` termina OK y la imagen no contiene toolchain Go
- [ ] El proceso corre con uid 1000 (`docker run --rm rodritv-api:test id` o inspección), nunca root
- [ ] El `HEALTHCHECK` apunta a `http://localhost:9291/healthz`
- [ ] La capa `go mod download` se cachea si solo cambia código fuente (rebuild sin cambios en go.mod no re-descarga módulos)

## Definición de finalizado (DoD):
- [ ] Dockerfile lint limpio (hadolint si está disponible; en su defecto revisión manual)
- [ ] Build de imagen verificado en local
- [ ] Tests existentes sin romper
- [ ] Código mergeado tras code review
- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
