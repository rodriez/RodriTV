# T-0067: Crear `build/web/Dockerfile` multi-stage

## Descripción técnica:
Crear `build/web/Dockerfile` [NUEVO] siguiendo exactamente el mismo patrón que `build/api/Dockerfile` (T-0066), pero compilando `./cmd/web` a `/out/rodritv-web`, binario runtime en `/app/rodritv-web`, `EXPOSE 9292` y `HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD wget -qO- http://localhost:9292/healthz || exit 1`. Mismas bases pinneadas (`golang:1.27-alpine`, `alpine:3.21`), `ca-certificates`, usuario `rodritv` uid 1000, `CGO_ENABLED=0 -trimpath -ldflags="-s -w"` y caché de capas con `go mod download`.

## Criterios de aceptación:
- [ ] Dado el binario `cmd/web` existente (EPIC-0003), `docker build -f build/web/Dockerfile -t rodritv-web:test .` termina OK
- [ ] El proceso corre con uid 1000, nunca root
- [ ] El `HEALTHCHECK` apunta a `http://localhost:9292/healthz`
- [ ] Misma estructura y convenciones que `build/api/Dockerfile` (revisable por diff)

## Definición de finalizado (DoD):
- [ ] Dockerfile lint limpio (hadolint si está disponible; en su defecto revisión manual)
- [ ] Build de imagen verificado en local
- [ ] Tests existentes sin romper

- [ ] Deployable de forma independiente (sin pasos manuales fuera del pipeline)
