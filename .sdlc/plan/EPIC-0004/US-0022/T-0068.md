# T-0068: Crear `build/playlist/Dockerfile` con ffmpeg, Chromium y yt-dlp pinneado

## Descripción técnica:
Crear `build/playlist/Dockerfile` [NUEVO]. Etapa build idéntica a T-0066 compilando `./cmd/playlist` a `/out/rodritv-playlist`. Runtime `FROM alpine:3.21`: `apk add --no-cache ca-certificates ffmpeg chromium`; yt-dlp como binario release pinneado con ARGs centralizados al tope del archivo: `ARG YTDLP_VERSION=<release actual>` y `ARG YTDLP_SHA256=<sha256 verificado de la release>`, `ADD https://github.com/yt-dlp/yt-dlp/releases/download/${YTDLP_VERSION}/yt-dlp /usr/local/bin/yt-dlp`, luego verificar `echo "${YTDLP_SHA256}  /usr/local/bin/yt-dlp" | sha256sum -c -` y `chmod +x`. El implementador fija `YTDLP_VERSION`/`YTDLP_SHA256` con la release vigente de yt-dlp en el momento de la tarea (descarga puntual) y deja ambos valores commiteados. Usuario no-root `rodritv` (uid 1000), binario `/app/rodritv-playlist`, `EXPOSE 9290`, `HEALTHCHECK ... wget -qO- http://localhost:9290/healthz || exit 1`, `ENTRYPOINT ["/app/rodritv-playlist"]`.

## Pseudo código:
```
ARG YTDLP_VERSION=2025.xx.xx          # pin: release vigente verificada
ARG YTDLP_SHA256=<sha256 del binario> # pin: coincide con la release
FROM golang:1.27-alpine AS build ... (patrón T-0066, ./cmd/playlist)
FROM alpine:3.21
apk add --no-cache ca-certificates ffmpeg chromium
ADD <url release yt-dlp> /usr/local/bin/yt-dlp
RUN echo "$YTDLP_SHA256  /usr/local/bin/yt-dlp" | sha256sum -c - && chmod +x /usr/local/bin/yt-dlp
... usuario no-root, EXPOSE 9290, HEALTHCHECK, ENTRYPOINT
```

## Criterios de aceptación:
- [ ] Dado un sha256 correcto, el build pasa; dado un sha256 adulterado, el build **falla** en la verificación
- [ ] En la imagen construida: `ffmpeg -version`, `yt-dlp --version` (reporta exactamente `YTDLP_VERSION`) y `chromium --version` existen y salen con código 0
- [ ] El proceso corre con uid 1000, nunca root
- [ ] El `HEALTHCHECK` apunta a `http://localhost:9290/healthz`
