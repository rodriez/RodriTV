# T-0023: Componer `cmd/playlist/main.go` con DI y graceful shutdown

## Descripción técnica:
Crear `cmd/playlist/main.go` [NUEVO]: punto de entrada que (1) carga `Config` (T-0020) y aborta con log claro si falla validación; (2) configura `slog` según `LogLevel` (handler JSON a stdout); (3) crea el pool pgx (T-0021); (4) construye el `ServeMux` con las rutas disponibles hasta el momento (`/healthz` con checker = ping de DB) vía `routes.go`; (5) crea y corre el server (T-0022). Señales: `signal.NotifyContext(SIGINT, SIGTERM)` como contexto raíz. Toda la composición vive en main; ningún paquete de `internal/` conoce al main. En esta US el main compila y corre sin motor (los componentes del motor se inyectan en T-0048).

## Pseudo código:
```
ctx = signal.NotifyContext(SIGINT, SIGTERM)
cfg = LoadConfig() o log.Fatal
slog.SetDefault(logger(cfg.LogLevel))
pool = platform.NewPool(ctx, cfg.DatabaseURL) o log.Fatal; defer pool.Close()
mux = http.NewServeMux(); registerRoutes(mux, deps{health: dbChecker{pool}})
srv = NewServer(cfg, withMiddleware(mux))
err = Run(ctx, srv, cfg.ShutdownTimeout); si err != http.ErrServerClosed: log.Error + exit 1
```

## Criterios de aceptación:
- [ ] `go build ./cmd/playlist` compila y `go vet ./...` está limpio
- [ ] Dado el binario corriendo con DB accesible, `GET /healthz` responde 200 y `SIGTERM` apaga en < `SHUTDOWN_TIMEOUT` con log de cierre ordenado
- [ ] Dado `DATABASE_URL` ausente, el binario sale con código != 0 y mensaje de validación
