# T-0044: Crear `PowerScheduler` con conjunto encendido en `internal/engine/scheduler.go`

## Descripción técnica:
Crear `internal/engine/scheduler.go` [NUEVO] con `PowerScheduler` puro (sin I/O; deterministic con `Clock` inyectable). Estado: mapa `channelNumber -> lastRequest time.Time` (thread-safe, mutex), alimentado desde `streamserver` (US-0015) vía `RecordRequest(channelNumber int)`. API: `PoweredSet(channels []catalog.Channel, cfg catalog.BehaviorConfig, started bool) []int` (números de canal encendidos): canal actual = el de request más reciente con antigüedad < `CurrentChannelTTL`; si ninguno y `!started` → los primeros `StartupChannels` por número (modo arranque); si ninguno y ya iniciado → el de menor número habilitado. Conjunto = actual ± `Neighbors` hacia atrás y adelante en la lista de habilitados ordenada por número, **circular** en los extremos (el vecino siguiente del último es el primero). Método `MarkStarted()` para salir del modo arranque cuando se detecta el primer canal actual. Función pura testeable: sin goroutines ni timers propios (el Engine la invoca en su tick).

## Pseudo código:
```
PoweredSet(channels, cfg, started):
    ordenados = enabled ordenados por number
    actual = argmax(lastRequest) con now-lastRequest < ttl
    si actual == nil: si !started: return primeros cfg.StartupChannels; si no: return [ordenados[0]]
    idx = índice de actual; resultado = {actual} ∪ {ordenados[(idx±k) mod len], k=1..cfg.Neighbors}
```

## Criterios de aceptación:
- [ ] 10 canales, actual=5, neighbors=2 → encendidos {3,4,5,6,7}
- [ ] Actual en el extremo (canal 1 de 10, neighbors=2) → conjunto circular incluye {9,10,1,2,3}
- [ ] Sin requests y sin arrancar → primeros `StartupChannels`; con TTL vencido (Clock fake) → canal de menor número
- [ ] Canal deshabilitado nunca entra al conjunto aunque tenga requests registradas
- [ ] Race-free: `RecordRequest` concurrente con `PoweredSet` (`go test -race`)
