# T-0045: Crear `Engine` con diffs de supervisores y config en caliente en `internal/engine/engine.go`

## Descripción técnica:
Crear `internal/engine/engine.go` [NUEVO] con `Engine` (1 goroutine raíz, `golang.org/x/sync/errgroup` vía `go mod tidy`): posee `PowerScheduler` (T-0044), mapa `channelNumber -> *ChannelSupervisor` (con su cancel), y consume `catalog.Watcher` (T-0027). API: `New(deps...) *Engine`, `Run(ctx) error`, `Running() bool` (para `/healthz`), `Scheduler() *PowerScheduler` (lo usa streamserver para `RecordRequest`). `Run`: errgroup con el watcher + loop principal (ticker 15 s + select sobre `watcher.Changes()`). En cada evaluación: `set = scheduler.PoweredSet(snap.Channels, snap.Config, started)`; diff contra el mapa: canales a encender → crear `ChannelSupervisor` y lanzarlo con ctx hijo; canales a apagar → cancelar y esperar (con timeout de 10 s por canal, log si excede). Cambios de `BehaviorConfig` (`buffer_minutes`, `uptime_threshold`, etc.) se propagan a los supervisores vivos vía método `ApplyConfig(cfg)` (reconfigura ventanas/umbrales sin reiniciar ffmpeg). Canal con cambios de contenido (sources editadas) → apagar y re-encender ese supervisor (diff por comparación del `catalog.Channel`). Cancelación de ctx raíz: apaga todos los supervisores ordenadamente (SHUTDOWN_TIMEOUT) y retorna.

## Pseudo código:
```
Run(ctx):
    eg.Go(watcher.Run)
    loop select { tick 15s | snap := <-watcher.Changes() | <-ctx.Done() }:
        aplicar snap (guardar último)
        set = scheduler.PoweredSet(...)
        apagar supervisores fuera de set o con Channel modificado
        encender supervisores nuevos (ctx hijo, eg)
        para vivos: ApplyConfig(snap.Config) si cambió
    shutdown: cancelar todos, esperar con timeout, retornar
```

## Criterios de aceptación:
- [ ] Snapshot inicial con 5 canales y startup_channels=3 → 3 supervisores encendidos (fake supervisor que registra start/stop)
- [ ] `RecordRequest(canal 4)` + tick → se enciende el conjunto alrededor de 4 y se apagan los que salen, con espera de apagado
- [ ] Cambio de `neighbors` en el siguiente snapshot → el conjunto crece/achica sin reiniciar supervisores que siguen en el conjunto
- [ ] Cambio de sources de un canal → ese supervisor se reinicia (stop+start); los demás no
- [ ] Cancelar ctx apaga todo dentro del timeout, sin goroutines huérfanas (`go test -race`); `Running()` refleja el estado
