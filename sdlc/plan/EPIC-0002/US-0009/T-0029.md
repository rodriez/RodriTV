# T-0029: Crear logger de procesos con rotación en `internal/proclog/logger.go`

## Descripción técnica:
Crear `internal/proclog/logger.go` [NUEVO] con `ProcLogger`: por proceso (canal + source + binario) escribe el stderr/stdout crudo completo a `${LOGS_DIR}/canal-<number>-src-<slot>-<process>.log` (rutas con `filepath.Join` sobre base fija, nombres generados internamente) con rotación lumberjack (10 MB × 3 archivos, `gopkg.in/natefinch/lumberjack.v2` vía `go mod tidy`). API: `New(logsDir string) *ProcLogger`, `Writer(channelNumber, slot int, process string) io.WriteCloser` (writer con buffer circular de las últimas 50 líneas accesible vía `Tail(channelNumber, slot, process) []string` para componer el resumen estructurado que `SourceProcess` envía a `process_logs`), y `Close() error`. Thread-safe (mutex por writer; un `ProcLogger` compartido por todo el motor).

## Pseudo código:
```
Writer(ch, slot, proc):
    key = fmt.Sprintf("canal-%d-src-%d-%s", ch, slot, proc)
    lj = &lumberjack.Logger{Filename: join(logsDir, key+".log"), MaxSize: 10, MaxBackups: 3}
    w = multiWriter(lj, ringBuffer(50 líneas)); guardar en map[key]
Tail(key): copiar las últimas 50 líneas del ring buffer
```

## Criterios de aceptación:
- [ ] Dado `t.TempDir()` como logsDir, escribir N líneas vía `Writer` genera el archivo con el nombre esperado y contenido completo
- [ ] `Tail` devuelve las últimas 50 líneas (o menos si hay menos), en orden
- [ ] Dado dos goroutines escribiendo al mismo proceso, no hay race (`go test -race`) ni líneas corruptas
- [ ] La rotación se produce al superar 10 MB (verificable con MaxSize bajo inyectado en test)
