# T-0032: Implementar extractor YouTube con yt-dlp en `internal/extractor/youtube.go`

## Descripción técnica:
Crear `internal/extractor/youtube.go` [NUEVO] con `YouTubeExtractor` (implementa `Extractor`, T-0030). `Resolve`: ejecuta `exec.CommandContext(ctx, ytdlpPath, "-f", "best", "-g", src.URL)` con timeout de 30 s (context.WithTimeout propio), parsea stdout por líneas y toma la primera URL no vacía. Exit code != 0 → error con comando completo, exit code y stderr (últimas líneas) para que el `SourceProcess` lo registre en `process_logs` (US-0009). `RefreshInterval` = 10 min siempre (streaming rotativo: la re-resolución contra la URL del canal `/live` descubre el vivo actual). El path del binario se recibe por constructor desde `BinariesConfig` (T-0030). Tests con binario fake (script shell en `t.TempDir()` que emula salida de yt-dlp: éxito, fallo con exit 1, lentitud > timeout).

## Pseudo código:
```
Resolve(ctx, src):
    ctx, cancel = WithTimeout(ctx, 30s)
    out, err = CommandContext(ytdlpPath, "-f", "best", "-g", src.URL).Output() // captura stderr aparte
    si ctx.DeadlineExceeded: error "yt-dlp timeout"
    si err: error "yt-dlp -f best -g <url>: exit <code>: <stderr tail>"
    return StreamURL{URL: primera línea no vacía de out}
```

## Criterios de aceptación:
- [ ] Binario fake que imprime una URL: `Resolve` la devuelve y `RefreshInterval` = 10 min
- [ ] Binario fake con exit 1 y stderr: el error incluye comando, exit code y stderr
- [ ] Binario fake que duerme 60 s: `Resolve` falla por timeout a los 30 s y mata el proceso
- [ ] Salida multilínea: se toma la primera línea no vacía
