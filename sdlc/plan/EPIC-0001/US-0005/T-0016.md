# T-0016: Crear dominio `metric`: queries sqlc y repositorio de uptime

## Descripción técnica:
Crear `internal/metric/entity.go` [NUEVO]: tipos `Window` (parse de `1h|24h|7d|30d` a `time.Duration`, default `24h`, inválido → error de validación), `ChannelMetrics` (`ChannelID`, `Window`, `Uptime float64`, `Sources []SourceMetrics`, `Interruptions int`) y `SourceMetrics` (`SourceID`, `Slot`, `Uptime`, `Active bool`, `State string`). `gateways.go` [NUEVO]: interfaz `Repository` (`Samples(ctx, channelID, since)`). `scripts/sqlc/metric.sql` [NUEVO]: query agregada sobre `uptime_samples` (`SUM(ok_count)/SUM(total_count)` por `source_id, source_slot` en la ventana, y conteo de interrupciones: transiciones a ventana sin señal sana — definir como cambios de ok→0 consecutivos en las muestras globales del canal, `source_id IS NULL`). `postgres.go` [NUEVO]: implementación.

## Pseudo código:
```
// cálculo de interrupciones
muestrasGlobales = samples donde source_id IS NULL ordenadas por ts
interruptions = cantidad de i donde muestras[i].ok==0 y muestras[i-1].ok>0
```

## Criterios de aceptación:
- [ ] Con samples sintéticos sembrados, el uptime calculado coincide con ok/total por source
- [ ] `window=2h` → 400 `validation`; `window` ausente usa 24h
- [ ] Conteo de interrupciones correcto ante secuencia ok→fail→ok→fail (= 2)
