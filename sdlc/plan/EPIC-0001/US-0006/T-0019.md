# T-0019: Crear job de retención en `internal/maintenance`

## Descripción técnica:
Crear `internal/maintenance/cleanup.go` [NUEVO]: struct `Cleaner` con `NewCleaner(pool *pgxpool.Pool, log *slog.Logger, retention time.Duration, now func() time.Time)` y método `Run(ctx)` que ejecuta un ticker diario a las 04:00 hora local (calcular el próximo disparo; tras cada ejecución reprogramar): `DELETE FROM uptime_samples WHERE ts < now() - interval` y lo mismo para `process_logs` (retención 35 días), logueando filas eliminadas. Errores se loguean y no detienen el proceso. Arrancar como goroutine en `main.go` tras las migraciones; se detiene con el contexto de shutdown. Test: reloj inyectado + testcontainers verificando que filas viejas se eliminan y las recientes no.

## Pseudo código:
```
para:
    next = próxima 04:00 local desde now()
    select { <-ctx.Done(): return; <-timer(next) }
    exec DELETE ... (cutoff = now() - 35d) para ambas tablas; log rows affected
```

## Criterios de aceptación:
- [ ] Con samples de 40 días y de 1 día, tras el run solo quedan los de 1 día
- [ ] El job respeta el contexto de shutdown (no deja goroutine colgada)
- [ ] Un error de DB se loguea y el job sigue programando el próximo ciclo
