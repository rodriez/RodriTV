# T-0010: Implementar `Service` de canales en `internal/channel/service.go`

## Descripción técnica:
Crear `internal/channel/service.go` [NUEVO]: struct `Service` con constructor `NewService(repo Repository, now func() time.Time) *Service` y métodos `List`, `Get`, `Create`, `Update`, `Delete` que orquestan: validación de dominio (`Validate`), chequeo de conflicto de `number` vía `ExistsNumber`, normalización (default `SegmentSeconds=5`, `Enabled=true` si no se especifica), generación de `ID`/`CreatedAt` de sources nuevas (uuid v4, conservando ids de sources existentes en Update por posición/id), propagación de errores de dominio. En `Delete`, si el canal tiene `Logo`, eliminar el archivo `${DATA_DIR}/logos/<logo>` (a través de una dependencia `LogoStore` mínima definida en el propio paquete — ver T-0012). Tests con `testify/mock` del `Repository` (único extremo).

## Criterios de aceptación:
- [ ] Crear con `number` ya usado devuelve `ErrConflict` sin llamar a `Create` del repo
- [ ] Crear sin `segment_seconds` persiste 5; fuera de 2–10 devuelve `ErrValidation`
- [ ] En Update, una source que ya tenía `id` lo conserva; una nueva recibe UUID v4 y timestamps
- [ ] Delete de canal inexistente propaga `ErrNotFound`
