# T-0055: Implementar métodos de config, métricas y logs en `internal/apiclient/client.go`

## Descripción técnica:
Completar `internal/apiclient/client.go` [NUEVO] con los 4 métodos restantes de `APIClient`: `GetConfig` → `GET /v1/config`; `PutConfig` → `PUT /v1/config` (reemplazo total); `GetMetrics` → `GET /v1/channels/{id}/metrics?window={w}` (validación local mínima: window vacía → `24h`; la validación de valores la hace la API y se propaga el 400); `GetLogs` → `GET /v1/channels/{id}/logs?level={l}&limit={n}&offset={m}` (level vacío → `all`, limit 0 → 100). Tests con `httptest.Server` por método, incluyendo 400 por `window` inválida y 404 por canal inexistente.

## Pseudo código:
```
GetMetrics(ctx, id, window):
    si window == "": window = "24h"
    q = url.Values{"window": {window}}
    do(GET, "/channels/"+esc(id)+"/metrics", q, nil, &m) → retornar m
GetLogs(ctx, id, level, limit, offset):
    defaults level=all, limit=100
    q = {level, limit, offset}; do(GET, "/channels/"+esc(id)+"/logs", q, nil, &lr) → lr
```

## Criterios de aceptación:
- [ ] `GetConfig` decodifica las 5 claves del contrato (`neighbors`, `startup_channels`, `current_channel_ttl_minutes`, `buffer_minutes`, `uptime_threshold`)
- [ ] `PutConfig` ante 400 con `fields.uptime_threshold` devuelve `APIError` de validación con ese field
- [ ] `GetMetrics(ctx, id, "")` envía `window=24h`; ante 400 por window inválida propaga el `APIError`
- [ ] `GetLogs` serializa `level`, `limit` y `offset` como query params y decodifica `logs` + `total`
- [ ] Cobertura de `apiclient` ≥ 75% tras esta tarea
