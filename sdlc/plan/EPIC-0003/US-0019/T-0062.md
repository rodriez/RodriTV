# T-0062: Crear fragmentos de edición y borrado de canal con grilla de 5 slots

## Descripción técnica:
Agregar a `internal/panel/fragments.go` [NUEVO]:
- `ChannelUpdateFragment`: `POST /frag/channels/{id}` — reutiliza `parseChannelForm` (T-0061) preservando `ID` de path y los `Source.ID` de slots ocupados (inputs hidden `slot_id_1..5` para no regenerar ids estables, SPECS-001.5.2) → `api.UpdateChannel` (reemplazo total con las 5 posiciones) → éxito: fragmento detalle re-renderizado + `HX-Trigger: channelsChanged`; errores: mismo mapeo que T-0061 (400 inline, 409 number, 404 → aviso + refresh lista, red → banner).
- `ChannelDeleteFragment`: `POST /frag/channels/{id}/delete` (confirmación con `hx-confirm`) → `api.DeleteChannel` → éxito: fragmento lista refrescada + detalle vacío con mensaje "canal eliminado"; 404 → lista refrescada con aviso; red → banner.
Registrar ambas rutas en `cmd/web/routes.go`. Tests con `APIClient` mockeado cubriendo cada rama de error.

## Pseudo código:
```
ChannelUpdateFragment:
    ch, ferr = parseChannelForm(r); ch.ID = pathValue("id")
    si ferr: form con errores; return
    _, err = api.UpdateChannel(ctx, ch.ID, ch)
    switch: IsValidation → form + Fields | IsConflict → error number | IsNotFound → aviso + lista | red → banner
    ok → render channel_detail{ch} + HX-Trigger channelsChanged
```

## Criterios de aceptación:
- [ ] Al editar, los `Source.ID` existentes llegan a la API sin cambios (verificado en el mock) y los slots vaciados en el form llegan como `null`
- [ ] Dado 400 con `fields["sources"]`, el error se muestra sobre la grilla de slots
- [ ] Dado 404 en update o delete, la respuesta incluye la lista refrescada y el aviso correspondiente
- [ ] Dado borrado exitoso, el main queda en estado vacío y la lista ya no muestra el canal
- [ ] Cobertura de `panel` ≥ 75% tras esta tarea
