# T-0064: Crear página de monitoreo con tarjetas de uptime por canal

## Descripción técnica:
Agregar a `internal/panel/pages.go` el handler `MonitoringPage`: `GET /monitoring` → `api.ListChannels`; por cada canal llama `api.GetMetrics(ctx, id, window)` con `window` del query param (`24h` default; selector 1h/24h/7d/30d que recarga la página con el param) → renderiza `pages/monitoring.html` [NUEVO]: una tarjeta por canal (nombre, número, uptime formateado con `formatUptime`, contador de interrupciones, lista de sources con `stateClass` y estado active/standby). Las llamadas a métricas son por canal con `errgroup`-free (secuencial es aceptable para N chico; un canal con error → tarjeta con banner "sin datos" sin romper la página). Registrar la ruta en `cmd/web/routes.go`. Tests con `APIClient` mockeado (mezcla de canales OK / 404 / error de red).

## Pseudo código:
```
MonitoringPage(w, r):
    window = r.URL.Query("window") o "24h"
    channels, err = api.ListChannels(ctx); si err red: página con banner; return
    cards = []
    para cada ch en channels:
        m, err = api.GetMetrics(ctx, ch.ID, window)
        si err: cards += {Channel: ch, SinDatos: true}
        sino: cards += {Channel: ch, Metrics: m}
    render.Render(w, "monitoring.html", {Cards: cards, Window: window})
```

## Criterios de aceptación:
- [ ] Dado 3 canales con métricas OK, la página muestra 3 tarjetas con uptime e interrupciones
- [ ] Dado un canal cuya API de métricas devuelve 404, su tarjeta muestra "sin datos" y las demás se renderizan igual
- [ ] `GET /monitoring?window=7d` propaga `window=7d` a todas las llamadas `GetMetrics` (verificado en el mock)
- [ ] Cada tarjeta enlaza a `/channels/{id}` (navegación al detalle del canal)
